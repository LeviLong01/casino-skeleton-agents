# Player win-rate flag for basic_17 vs standard_17 — likely false positive from small sample + inherent "mimic-the-dealer" disadvantage, not a logic defect

- **Pairing:** basic_17 vs standard_17
- **Severity:** low
- **Detected:** 20260819T200907Z

## Evidence
Observed over 50 rounds: win=28.0%, loss=70.0%, push=2.0%, bust=36.0%. Configured expected range for player win rate is 30%-55%; 28.0% breaches only the lower bound by 2 points. Bust rate of 36% is consistent with a strategy that hits purely on hand total (<17) with no regard for dealer_upcard (BasicPlayerStrategy.should_hit ignores dealer_upcard entirely), and Table.play_round() resolves player busts as an immediate dealer win before the dealer even draws, structurally capping player win rate below dealer win rate for any strategy that mirrors the dealer's stand-on-17 rule.

## Likely cause
The player strategy (BasicPlayerStrategy, name="basic_17") hits until hand.value() >= 17, which is *identical* logic to the dealer's StandardDealerStrategy (also hits < 17). Table.play_round() has the player act completely before the dealer draws any additional cards, and a player bust is resolved as an immediate loss without ever letting the dealer's hand play out ("if player_hand.is_bust(): return self._outcome('dealer', ...)"). Because both sides use the same threshold, but the player is forced to commit to hit/stand decisions first, the player absorbs the full cost of busting (36% here) while the dealer only busts on hands the player has already survived. This is the well-known structural disadvantage of a "mimic the dealer" strategy — it does not use the dealer's up-card at all (should_hit ignores dealer_upcard) and has no soft-hand/double/split logic, so its true expected win rate sits at the low end of (or slightly below) a typical 30–55% band even when the code is functioning correctly. With only 50 rounds sampled, the standard error on a win-rate estimate near 30% is roughly sqrt(0.3*0.7/50) ≈ 6.5 percentage points, so a 28% observed rate is well within one standard deviation of a 30% true rate — i.e., this looks like normal small-sample variance around an already-thin margin, not a bug in Hand.value(), Deck dealing order, or Table's outcome resolution.

## Recommendation
Before treating this as a real regression, re-run the pairing for a much larger sample (e.g., 1,000–5,000 rounds) to shrink the confidence interval and see if win rate stabilizes above 30%; a single 50-round batch is too small to reliably distinguish a real strategy/logic bug from expected variance this close to the threshold. In parallel, have an engineer confirm whether the 30%-55% expected band was calibrated using a proper basic-strategy player (one that considers dealer_upcard and soft totals) versus this simplistic 'mimic the dealer' BasicPlayerStrategy — if the latter is intentional as a baseline/control, the expected range for the basic_17 vs standard_17 pairing specifically should be widened/lowered rather than continuing to fire alerts on statistically-expected outcomes.
