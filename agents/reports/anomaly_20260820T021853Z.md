# basic_17 vs standard_17 win-rate dip likely explained by small sample size + inherent player-disadvantage of "mimic dealer" strategy, not a code defect

- **Pairing:** basic_17 vs standard_17
- **Severity:** low
- **Detected:** 20260820T021853Z

## Evidence
Observed over 50 rounds: win=28.0%, loss=58.0%, push=14.0%, bust=36.0%. Monitor threshold expected player win rate range 30%-55%; 28.0% falls just outside the lower bound. Bust rate (36%) accounts for most of the loss rate (58%), consistent with the code path in Table.play_round() where a player bust is resolved as an immediate dealer win before the dealer strategy ever runs (self.dealer_strategy.should_hit is never invoked in that branch). Sample size is only n=50 rounds, which is small for a metric whose expected variance (~±7pp at p≈0.35-0.40) can easily push observed win rate below a 30% floor by chance alone.

## Likely cause
Both BasicPlayerStrategy and StandardDealerStrategy use the identical "hit until 17" rule, but the Table.play_round() logic resolves the player's turn completely before the dealer plays at all (player_hand.is_bust() is checked and returned as a dealer win before the dealer draws a single extra card). This means any hand where the player strategy busts is an automatic loss, while the dealer only busts in the remaining scenarios and never against an already-busted player. This "acts-first" asymmetry is the classic source of house edge in blackjack even when player/dealer hit-thresholds are identical, and typically yields player win rates in the mid-30s to high-30s% range (not 50/50). With only 50 rounds sampled, the sampling standard error on a win-rate metric with true probability ~0.35-0.40 is roughly ±7 percentage points, so an observed 28% is only ~1-1.5 standard deviations from a plausible true mean - well within normal variance for this sample size, not necessarily indicative of a bug in Table, Hand, or the strategy classes (which all look logically correct: value(), is_bust(), and the hit loops all match standard blackjack rules).

## Recommendation
Before treating this as a strategy or engine defect, re-run the same basic_17 vs standard_17 pairing for a much larger sample (e.g., 5,000-10,000 rounds) to shrink the confidence interval and confirm whether the win rate stabilizes above 30% (expected theoretical value for this matchup) or remains persistently low. If it remains low at scale, audit casino/cards.py's Deck implementation (not shown here) for shuffle bias or non-uniform card distribution, since that is the only unreviewed component that could introduce a genuine statistical skew beyond the expected house edge from the play-order asymmetry.
