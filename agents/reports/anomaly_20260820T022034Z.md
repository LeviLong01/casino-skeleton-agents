# Elevated bust/loss rate for aggressive_20 player strategy vs standard_17 dealer

- **Pairing:** aggressive_20 vs standard_17
- **Severity:** medium
- **Detected:** 20260820T022034Z

## Evidence
Observed over 50 rounds: win=22.0% (below expected 30-55% range), loss=74.0%, push=4.0%, bust=72.0% (exceeds 40% ceiling). Root cause traced to AggressivePlayerStrategy.should_hit() returning True for hand.value() < 20, causing the player to hit on 17/18/19 hands where busting probability is high, directly driving both the excessive bust rate and the correspondingly low win rate.

## Likely cause
The anomaly is expected behavior from a known-bad strategy fixture, not a system defect. AggressivePlayerStrategy.should_hit() in casino/strategies.py hits on any hand value < 20, meaning the player continues drawing cards on totals like 17, 18, and 19 where standard basic strategy would stand. Since a large fraction of card draws (10-value cards: 10,J,Q,K plus many mid-value cards) push totals over 21 when starting from 17-19, this strategy is mathematically guaranteed to bust far more often than the standard 'hit below 17' rule. The docstring explicitly notes this is 'deliberately over-aggressive... kept as a stress-test fixture so the anomaly monitor has real, occasional signal to react to,' confirming this is intentional test/fixture logic rather than a bug in Table.play_round(), Hand.value(), or the dealer logic.

## Recommendation
No code fix required for correctness — verify this pairing (aggressive_20 vs standard_17) is intentionally included in the monitored test matrix as a stress-test/canary fixture. If it should not trigger paging/alerting, add it to an exclusion list or tag it as 'expected anomaly' in the monitor config so it doesn't generate noisy incidents. If aggressive_20 is unintentionally reachable by real player-facing simulations, restrict it to test-only strategy registries and confirm production traffic never selects it.</recommendation>
