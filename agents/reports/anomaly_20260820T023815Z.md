# Elevated player bust rate for aggressive_20 vs standard_17 pairing

- **Pairing:** aggressive_20 vs standard_17
- **Severity:** medium
- **Detected:** 20260820T023815Z

## Evidence
Over 50 rounds of aggressive_20 vs standard_17: bust=54.0% (ceiling 40%), win=38.0%, loss=56.0%, push=6.0%. AggressivePlayerStrategy.should_hit() hits while hand.value() < 20, versus BasicPlayerStrategy's threshold of < 17, directly increasing draws on hands in the 12-19 range that are bust-prone.

## Likely cause
The player_bust rate breach is an expected consequence of the AggressivePlayerStrategy's design in casino/strategies.py. Its should_hit() method returns True for any hand value < 20, meaning the player will keep drawing cards on hard totals of 18 and 19 (and anything below 20) where standard strategy would stand. Hitting on 18/19 carries a very high probability of busting (any 4+ card pushes an 18 over 21, any 3+ pushes a 19 over 21), so the aggressive_20 strategy structurally trades a higher bust rate for the chance of reaching a stronger final total. This is not a bug in Table.play_round or Hand.value() — both correctly compute totals and bust conditions — it is the intrinsic behavior of the 'stress-test fixture' strategy, which the code comments explicitly note is 'deliberately over-aggressive... kept in the strategy library... so the anomaly monitor has real, occasional signal to react to.'

## Recommendation
Confirm this is the intended fixture behavior rather than a regression: check monitor/alert config to see if aggressive_20 should be excluded from production anomaly alerting (e.g., via an allowlist/known-fixture tag) since it is documented as a deliberately over-aggressive stress-test strategy. If aggressive_20 is not meant to run against live/production tables, verify table configuration to ensure it isn't accidentally paired with real players, and restrict its use to test/monitoring environments only.
