# False-positive anomaly: basic_17 vs standard_17 win-rate spike likely statistical noise from small sample (n=50)

- **Pairing:** basic_17 vs standard_17
- **Severity:** low
- **Detected:** 20260819T210531Z

## Evidence
Monitor flagged player win rate 56.0% (loss 40.0%, push 4.0%, bust 22.0%) against an expected band of 30%-55%, but this is derived from only 50 rounds. Code inspection shows both strategies share the same 17-threshold rule and each round uses a freshly instantiated Deck(1) with no persisted shoe state, so there is no mechanism in table.py/strategies.py/hand.py that would durably shift outcome probabilities toward the player. The push rate (4%) is also anomalously low relative to typical single-deck blackjack push rates (~8-9%), further suggesting sampling noise rather than a systemic effect.

## Likely cause
There is no logic bug in Table.play_round(), Hand.value(), or the strategy classes that would systematically favor the player. Both basic_17 (player) and standard_17 (dealer) use the identical 'hit while value < 17' rule, and Table.play_round() creates a brand-new full Deck(1) every round (no shoe depletion/carry-over between rounds), so each round is an independent trial with the same underlying probabilities every time. If anything, the game loop gives the dealer a structural edge, not the player: the player acts first and an immediate player bust is scored as a dealer win before the dealer ever has to act (see play_round: 'if player_hand.is_bust(): return self._outcome(\"dealer\", ...)'), so the theoretical player win rate should sit at or below the ~50% midpoint the monitor is centered on. Given that, a 56% win rate over only 50 rounds is well within ordinary sampling variance for a Bernoulli-ish outcome with p in the 40-50% range (standard error ≈ sqrt(0.45*0.55/50) ≈ 7 percentage points, so 56% is roughly only ~1.5σ from a 45% baseline). The unusually low push rate (4% vs a typically expected ~8-9%) is consistent with this being a small, noisy sample rather than a real behavioral shift in either strategy.

## Recommendation
Before treating this as a real strategy/engine defect, re-run the basic_17 vs standard_17 pairing for a much larger sample (e.g., 5,000-10,000 rounds) and recompute the win/loss/push/bust rates; if they settle back within/near the expected band, close this as a false positive. Longer term, have the anomaly monitor use a statistical significance test (e.g., a z-test or confidence interval scaled to sample size, such as Wilson score interval) instead of a fixed percentage band, so alerts at n=50 aren't triggered by ordinary variance.
