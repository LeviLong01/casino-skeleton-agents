## Likely cause
The flagged pairing uses BasicPlayerStrategy (name="basic_17"), whose should_hit() correctly implements standard basic strategy: hit while hand.value() < 17. This is the textbook player rule and is expected to bust in roughly 28-30% of rounds long-run, not the deliberately over-aggressive AggressivePlayerStrategy ("aggressive_20", hits until 20) that the codebase comments explicitly flag as a stress-test fixture for triggering this exact monitor. Hand.value()/is_bust() logic is also standard and correctly handles ace soft/hard totals, so there is no code-level bug causing extra busts. Given the sample size is only 50 rounds, a 42% observed bust rate is a plausible statistical fluctuation around the true ~28-30% bust rate for basic_17 (a swing of this size falls within ~2 standard errors for n=50), rather than evidence of a logic error in Table.play_round, BasicPlayerStrategy, or Hand.

## Recommendation
Before treating this as a code/logic incident, re-run the monitor over a larger sample (e.g., 1,000+ rounds) for the basic_17 vs standard_17 pairing to see if the bust rate reverts toward the expected ~28-30% baseline. If it stabilizes near 40%+ over a large sample, then audit Deck/card draw randomness (casino/cards.py, not shown here) for a shoe-composition or shuffling bug rather than the strategy classes, since should_hit() and Hand.value() logic both appear correct. Also consider tuning the bust-rate ceiling or adding a minimum-sample-size gate to the anomaly monitor to reduce false positives on 50-round windows.
