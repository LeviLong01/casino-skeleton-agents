# Elevated player bust rate (60%) for aggressive_20 vs standard_17 pairing

- **Pairing:** aggressive_20 vs standard_17
- **Severity:** low
- **Detected:** 20260820T022748Z

## Evidence
Over the last 50 rounds for aggressive_20 vs standard_17: win=34.0%, loss=62.0%, push=4.0%, bust=60.0%. Monitor threshold: player bust rate ceiling is 40%; observed 60.0% breaches this by 20 points. Loss rate (62.0%) closely tracks bust rate (60.0%), consistent with player_hand.is_bust() triggering an automatic dealer win via Table._outcome('dealer', ...) before the dealer even acts.

## Likely cause
The player strategy in this pairing is AggressivePlayerStrategy ("aggressive_20"), whose should_hit() logic keeps hitting until hand.value() >= 20 (i.e., it hits on any hand valued 12-19, including 18 and 19 which basic strategy would stand on). Since Hand.value() computes standard blackjack totals (soft-ace adjusted), hitting on hard/soft totals in the high-teens carries very high bust probability with a single deck (num_decks=1 further increases card depletion/variance). Per the strategies.py docstring, this strategy is "deliberately over-aggressive... kept in the strategy library as a stress-test fixture so the anomaly monitor has real, occasional signal to react to." The 60% bust rate is therefore the expected statistical consequence of the strategy's hit threshold, not a bug in Table.play_round, Hand.value/is_bust, or the deck/dealer logic, all of which behave correctly.

## Recommendation
Confirm this is the known stress-test fixture (strategies.py explicitly documents aggressive_20 as intentionally over-aggressive) rather than a production configuration error. If aggressive_20 is only meant for monitor validation, exclude this pairing from production anomaly alerting or tag it as an expected/whitelisted high-bust scenario so it doesn't trigger paging. If it is unexpectedly appearing in live play selection, audit the strategy-selection/config layer to ensure aggressive_20 is not being assigned to real player sessions, and consider adding a guard or comment flag (e.g., is_test_fixture=True) on AggressivePlayerStrategy to prevent accidental production use.
