# Anomalous player win-rate for basic_17 vs standard_17 (60% observed vs 30-55% expected band)

- **Pairing:** basic_17 vs standard_17
- **Severity:** medium
- **Detected:** 20260819T205851Z

## Evidence
Flagged stats over 50 rounds: win=60.0%, loss=28.0%, push=12.0%, bust=20.0%. Breached threshold: player win rate 60.0% outside expected 30%-55% band. Notably, bust rate (20%) is also below the ~28% typically expected for a flat "hit-until-17" strategy on both sides, which is inconsistent with the reviewed play_round() logic where the player resolves (and can bust) strictly before the dealer acts — a structural disadvantage that this code does not compensate for elsewhere (no double-down, no blackjack payout bonus visible in _outcome()).

## Likely cause
Both the player strategy (basic_17) and dealer strategy (standard_17) use the identical "hit until hand value reaches 17" rule, and Table.play_round() always resolves the player's turn (and any player bust) before the dealer even draws a card. This ordering inherently favors the dealer under equal thresholds — the player is the one exposed to busting first, so a fair implementation of this specific strategy pairing should typically produce a player win-rate noticeably *below* 50% (historically ~40-48%) with a correspondingly higher bust rate (commonly ~28% for a flat 17-stand threshold). The observed sample instead shows a *higher* win rate (60%) combined with a *lower* bust rate (20%) than that baseline, which is the opposite of what the game-theoretic order-of-play disadvantage predicts. Two plausible explanations, given only the code reviewed here: (1) the sample size (n=50) is small enough that this is within normal binomial variance (std dev ≈ 7% at p≈0.45, so 60% is only a ~2σ outlier) and the "anomaly" is a statistical false-positive rather than a logic bug; or (2) the bias originates in the unreviewed casino/cards.py Deck implementation (shuffle/draw order), since Table.play_round(), Hand.value(), and the strategy classes themselves contain no logic that would asymmetrically favor the player — e.g., a non-uniform shuffle, deck not being reset/reshuffled correctly between rounds, or a draw() bias toward low-value cards being handed preferentially in the player's draw slots.

## Recommendation
1) Re-run the basic_17 vs standard_17 pairing for a much larger sample (e.g., 5,000-10,000+ rounds) to determine whether 60% win rate persists outside the noise band expected at n=50 (~±7% stdev). 2) If the elevated win rate persists at scale, audit casino/cards.py's Deck class (not shown in this review) for shuffle correctness, proper reset per play_round() call, and any ordering bias in draw() that could systematically deal higher-value/safer cards to whichever hand draws first (the player). 3) Add a unit test that runs a large number of simulated rounds for symmetric strategies (basic_17 vs standard_17) and asserts the win/loss/bust distribution stays within a known analytically-derived confidence interval, so future monitor alerts can distinguish sampling noise from real regressions.
