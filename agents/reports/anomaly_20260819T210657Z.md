# Excessive player bust rate due to overly aggressive hit threshold in aggressive_20 strategy

- **Pairing:** aggressive_20 vs standard_17
- **Severity:** low
- **Detected:** 20260819T210657Z

## Evidence
Over 50 rounds of aggressive_20 vs standard_17: bust=70.0% (ceiling 40%), loss=72.0%, win=22.0% (expected range 30%-55%), push=6.0%. The strategy's should_hit() returns True whenever hand.value() < 20, causing repeated draws on already-strong hands (17-19) where any card ≥ 2 (and especially the abundant 10-value cards) causes a bust.

## Likely cause
The AggressivePlayerStrategy (name="aggressive_20") in casino/strategies.py hits on any hand value < 20, meaning the player will keep drawing cards on hands of 17, 18, and 19 — values that are already strong and, per basic blackjack strategy, should stand. Since the deck contains many 10-value cards (10, J, Q, K each worth 10) and aces, drawing an additional card on a 17-19 hand pushes the total over 21 far more often than a threshold of 17 would. This is explicitly documented in the source as a "deliberately over-aggressive" fixture kept in the strategy library specifically to stress-test the anomaly monitor, so the elevated bust/loss rate and depressed win rate are an expected, engineered outcome of this strategy pairing rather than a bug in table.py, hand.py, or the dealer logic.

## Recommendation
Confirm this is expected/simulated behavior: since AggressivePlayerStrategy is explicitly labeled in the code comments as a stress-test fixture for the anomaly monitor, no code fix is required if this run was intentional. If aggressive_20 is not supposed to be used in live/production simulations, exclude it from the active strategy pool or gate it behind a test-only flag so the monitor doesn't continue flagging expected-anomalous results as incidents. Optionally, tune the monitor's thresholds/whitelist to suppress alerts for known stress-test strategy pairings like aggressive_20 vs standard_17.
