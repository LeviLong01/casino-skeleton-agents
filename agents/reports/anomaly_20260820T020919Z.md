# Elevated player bust/loss rate for aggressive_20 vs standard_17 pairing

- **Pairing:** aggressive_20 vs standard_17
- **Severity:** low
- **Detected:** 20260820T020919Z

## Evidence
Over 50 rounds: win=24.0% (below expected range 30%-55%), loss=74.0%, push=2.0%, bust=70.0% (ceiling is 40%). The bust rate of 70% is consistent with hitting until hand value reaches 20, since starting hands frequently sit in the 12-19 range and additional draws to reach 20 have a substantial chance of busting (many card values 2-10 will push an 18-19 hand over 21). This matches the aggressive_20 strategy's should_hit(hand, dealer_upcard) returning True whenever hand.value() < 20, contrasted with the standard/basic threshold of 17.

## Likely cause
The anomaly is expected behavior, not a bug. AggressivePlayerStrategy (name="aggressive_20") in casino/strategies.py deliberately hits until the hand value reaches 20 (should_hit returns True while value < 20), rather than the standard threshold of 17. Because the player keeps drawing cards up to hand values of 18-19, the probability of drawing a card that pushes the total over 21 is much higher than under BasicPlayerStrategy's 17-threshold. This strategy's docstring explicitly states it is "deliberately over-aggressive... kept in the strategy library as a stress-test fixture so the anomaly monitor has real, occasional signal to react to." The Table.play_round logic correctly awards the round to the dealer immediately whenever player_hand.is_bust() is True, so the high bust rate directly and correctly translates into a high loss rate and depressed win rate. No defect exists in Table, Hand, or Deck logic — the outcome is the deterministic statistical consequence of the configured strategy pairing.

## Recommendation
Confirm with the team whether aggressive_20 is intentionally deployed as a stress-test/fixture strategy (per its docstring) or was mistakenly enabled in a live/production monitoring context. If intentional, whitelist this specific strategy pairing in the anomaly monitor's threshold config (or tag it as a known/expected-anomaly fixture) to prevent recurring false-positive alerts. If it was not intended to be active, revert the player strategy assignment to BasicPlayerStrategy (basic_17) or another vetted strategy for this table before continuing to collect performance stats.
