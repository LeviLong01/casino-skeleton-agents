# Elevated player bust rate for aggressive_20 strategy vs standard_17 dealer

- **Pairing:** aggressive_20 vs standard_17
- **Severity:** low
- **Detected:** 20260819T202514Z

## Evidence
Over 50 rounds of aggressive_20 vs standard_17: win=34.0%, loss=60.0%, push=6.0%, bust=56.0%, breaching the 40% player-bust ceiling. AggressivePlayerStrategy.should_hit() returns True for hand.value() < 20, causing hits at totals like 17, 18, 19 where standard/basic strategies would stand, sharply raising bust probability per Hand.is_bust() (value() > 21).

## Likely cause
This is expected behavior, not a system malfunction. AggressivePlayerStrategy (casino/strategies.py) is intentionally configured to keep hitting until hand.value() >= 20 (should_hit returns True while value < 20), rather than stopping at 17 like BasicPlayerStrategy. Since a large fraction of hands sit in the 12-19 range after the initial deal, this strategy forces many additional draws that would have been declined at the standard 17 threshold, mechanically increasing the probability of exceeding 21 (is_bust() in casino/hand.py). The code comment even notes this fixture is "deliberately over-aggressive... kept in the strategy library as a stress-test fixture so the anomaly monitor has real, occasional signal to react to." Table.play_round() and Hand.value()/is_bust() are functioning correctly per their logic; the anomaly is a direct, expected statistical consequence of pairing this fixture strategy against the monitor.

## Recommendation
Confirm this pairing is intentional test/fixture traffic (per the source comment) rather than a misconfigured production strategy assignment. If aggressive_20 is only meant for stress-testing the monitor, verify it is excluded from real-money/production table configs and, if desired, add an allowlist or separate alert threshold for known fixture strategies so it doesn't generate operational noise. If this pairing is unintentionally live, revert the player strategy assignment to basic_17.
