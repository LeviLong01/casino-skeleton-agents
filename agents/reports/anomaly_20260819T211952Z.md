## Likely cause
Unlike the aggressive_20 strategy (which is explicitly documented as an over-aggressive stress-test fixture and hits to 20), the basic_17/standard_17 pairing implements completely standard, symmetric blackjack logic: both player and dealer hit until hand value >= 17 (BasicPlayerStrategy.should_hit and StandardDealerStrategy.should_hit are identical `value() < 17` checks), and Table.play_round applies standard rules (player busts first if applicable, dealer only draws if player hasn't busted, higher final value wins, tie is a push). There is no logic bug in table.py, strategies.py, or hand.py that would structurally inflate the player's win rate for this pairing — if anything, the player acting (and busting) first should slightly favor the dealer, consistent with the 30-55% expected band being centered below 50%. With only 50 rounds sampled, the observed 58% win rate (~29/50 wins) is within ~2-2.5 standard deviations of a plausible true win rate in the mid-40s (SE ≈ 7 percentage points for p≈0.42-0.45, n=50), which is a small enough sample for this kind of overshoot to occur by chance, especially if the monitor's alert threshold isn't sample-size adjusted.

## Recommendation
Re-run the monitor over a much larger sample (e.g., 5,000-10,000 rounds) for the basic_17/standard_17 pairing to get a statistically stable win-rate estimate before treating this as a true anomaly; if the elevated rate persists at scale, audit casino/cards.py (Deck implementation/shuffle logic, not shown here) for shuffle bias or improper reshuffling between rounds, and consider tightening the monitor's alert bands to be sample-size-aware (e.g., using a confidence interval based on n) rather than a fixed 30-55% band for all sample sizes.
