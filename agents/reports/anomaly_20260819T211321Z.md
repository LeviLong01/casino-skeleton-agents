# Elevated bust/loss rate for aggressive_20 vs standard_17 pairing

- **Pairing:** aggressive_20 vs standard_17
- **Severity:** medium
- **Detected:** 20260819T211321Z

## Evidence
Over 50 rounds: win=28.0% (below expected 30%-55% range), loss=66.0%, push=6.0%, bust=58.0% (exceeds 40% ceiling ). No anomalies found in Hand.value()/is_bust() (standard blackjack bust-on-22 rule) or Table.play_round() outcome resolution logic — the bust/loss spike traces specifically to AggressivePlayerStrategy.should_hit() returning True for hand.value() < 20, an unusually high standing threshold compared to BasicPlayerStrategy's < 17.

## Likely cause
The player strategy "aggressive_20" (AggressivePlayerStrategy.should_hit) continues hitting on any hand valued below 20, meaning it will hit on hard 17, 18, and 19 totals — hands that basic strategy would stand on. Hitting on already-strong totals dramatically increases the probability of drawing a card that pushes the hand over 21, especially since any 5+ card (a large fraction of the shoe: 10/J/Q/K, plus mid-value cards on a 17-19 total) causes a bust. This directly inflates the observed 58% player bust rate versus the 40% ceiling, and consequently drags down the win rate (28%) since busted hands auto-lose per Table._outcome logic regardless of the dealer's subsequent play. The code comment in strategies.py explicitly confirms this is an intentionally over-aggressive fixture ("Deliberately over-aggressive... kept in the strategy library as a stress-test fixture so the anomaly monitor has real, occasional signal to react to"), indicating the behavior is a designed stress case rather than an unintended defect in Table, Hand, or Deck logic.

## Recommendation
Confirm with the team whether aggressive_20 is intended to run against production/monitored traffic or should be restricted to isolated stress-test runs. If it's meant purely as a fixture, exclude the aggressive_20 pairing from the live anomaly monitor's threshold checks (or tag it with a separate, wider threshold profile) to avoid false-positive incident noise. If aggressive_20 is unintentionally reachable by real strategy-selection logic, patch the selection/config to prevent it from being paired with real players, and add a unit test asserting bust rate for aggressive_20 stays within an expected stress-test band (e.g., 50-65%) so future changes don't silently alter its risk profile.
