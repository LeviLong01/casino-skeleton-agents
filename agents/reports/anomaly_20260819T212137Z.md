# Elevated Player Bust Rate for aggressive_20 vs standard_17 Pairing

- **Pairing:** aggressive_20 vs standard_17
- **Severity:** low
- **Detected:** 20260819T212137Z

## Evidence
Over 50 rounds: win=34.0%, loss=62.0%, push=4.0%, bust=56.0%. Player bust rate of 56.0% breaches the configured ceiling of 40%. Root cause traceable to AggressivePlayerStrategy.should_hit() returning `hand.value() < 20`, versus StandardDealerStrategy/BasicPlayerStrategy's more conservative `< 17` threshold — a 3-point higher hit ceiling that compounds bust risk across the 13-19 value range.

## Likely cause
The player_strategy in this pairing is AggressivePlayerStrategy (name="aggressive_20"), whose should_hit() method returns True for any hand value < 20 (casino/strategies.py). This means the player will keep hitting on totals like 12-19, which in standard blackjack are normally stand thresholds (basic strategy stands at 17+). Hitting on hands in the high teens dramatically increases the probability of drawing a card that pushes the total over 21, since roughly 9/13 remaining ranks (8 through K, i.e., 8,9,10,J,Q,K) will bust a 13+ hand and even more will bust a 17-19 hand. The class docstring explicitly confirms this is intentional: 'Deliberately over-aggressive: kept in the strategy library as a stress-test fixture so the anomaly monitor has real, occasional signal to react to.' The Table.play_round() logic correctly awards the round to the dealer whenever player_hand.is_bust() is True, so the 56% bust rate is a direct, expected mechanical consequence of the strategy's hit threshold, not a bug in Table, Hand, or Deck logic.

## Recommendation
No code fix is required in Table/Hand/Deck — behavior is correct given the strategy definition. Confirm with the team whether aggressive_20 is intended to remain in production strategy rotation or is solely a test fixture (per its docstring). If it's a deliberate stress-test fixture, suppress/whitelist this specific strategy pairing in the anomaly monitor's alerting rules (or tag it as 'expected-high-bust') to avoid recurring false-positive incidents. If it is unintentionally reachable by real players/config, gate AggressivePlayerStrategy behind a test-only flag or remove it from the selectable strategy list.
